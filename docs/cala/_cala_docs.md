# CALA Horizon Residual Learning for Nonlinear Disturbance Compensation

## Purpose

This document explains the role of the CALA horizon residual learner in the updated MPC architecture.

The core idea is:

> The MPC estimates the local input-channel disturbance online. CALA learns a residual correction to that local approximation by measuring how well the MPC prediction horizon matches the actual closed-loop trajectory.

This preserves the structure of the existing MPC controller while adding a learning layer that can adapt to nonlinear, spatially varying, and time-varying disturbance effects.

---

## Plant and Disturbance Model

The plant is assumed to evolve according to:

```math
x_{k+1} = A x_k + B\left(u_k + d(p_k,t_k)\right)
```

where:

```math
x_k =
\begin{bmatrix}
p_x & p_y & v_x & v_y
\end{bmatrix}^T
```

and:

```math
p_k =
\begin{bmatrix}
p_x \\
p_y
\end{bmatrix}
```

The disturbance:

```math
d(p_k,t_k) \in \mathbb{R}^{n_u}
```

is an input-channel disturbance. It enters through the same matrix as the commanded input. In the current implementation, this disturbance is generated by the nonlinear vortex field.

The physical plant therefore receives the effective input:

```math
u_{\text{effective},k} = u_k + d(p_k,t_k)
```

The controller does not know the true nonlinear function `d(p,t)`. It only observes the plant state and estimates the disturbance from prediction error.

---

## Existing MPC Disturbance Estimate

The current MPC already estimates the local input-equivalent disturbance online.

At time step `k`, the controller compares the measured state against the one-step prediction from the previous state and previous input:

```math
e_k = x_k - A x_{k-1} - B u_{k-1}
```

The disturbance estimate is obtained by solving:

```math
B\hat d_k \approx e_k
```

or equivalently:

```math
\hat d_k = B^{\dagger} e_k
```

In code, this corresponds to:

```python
prediction_error = self.x0 - self.A @ self.x_prev - self.B @ self.u_prev
self.d_hat, _, _, _ = np.linalg.lstsq(self.B, prediction_error, rcond=None)
```

This means `d_hat` is a local estimate of the current disturbance value.

If the true disturbance is nonlinear:

```math
d_k = d(p_k,t_k)
```

then the MPC estimate acts like a zeroth-order local approximation:

```math
d(p,t) \approx \hat d_k
```

near the current operating point.

---

## How the Disturbance Estimate Enters the MPC Horizon

The MPC predicts future states using lifted horizon matrices:

```math
S = A_{\text{aug}}x_k + B_{\text{aug}}U + D_{\text{aug}}\hat d_k
```

where:

- `S` is the stacked predicted state sequence over the horizon;
- `U` is the stacked input sequence;
- `D_aug d_hat` is the disturbance offset over the horizon.

This means the MPC assumes the current disturbance estimate remains constant over the prediction horizon:

```math
d_{k+i} \approx \hat d_k, \quad i = 0,1,\dots,h-1
```

This is reasonable when the disturbance varies slowly over the prediction horizon. However, if the disturbance field is nonlinear or time-varying, the approximation can degrade as the predicted trajectory moves through the field.

---

## Why CALA Is Added

The online MPC disturbance estimate is useful, but it only estimates the current local disturbance. It does not learn a reusable nonlinear map:

```math
(p,t) \mapsto d(p,t)
```

Instead, it estimates only:

```math
\hat d_k \approx d(p_k,t_k)
```

CALA is added to learn the residual error in this approximation.

Rather than learning the full disturbance field directly, CALA learns a correction:

```math
\Delta d_{\text{CALA},k}
```

The effective disturbance estimate used by MPC becomes:

```math
\hat d_{\text{eff},k}
=
\hat d_k + \Delta d_{\text{CALA},k}
```

The MPC prediction becomes:

```math
S
=
A_{\text{aug}}x_k
+
B_{\text{aug}}U
+
D_{\text{aug}}\left(\hat d_k + \Delta d_{\text{CALA},k}\right)
```

This creates the intended architecture:

> MPC estimates the local disturbance. CALA learns how that local estimate should be corrected across nonlinear regions of the state space.

---

## CALA Action Interpretation

The CALA action is an additive disturbance correction:

```math
\Delta d_{\text{CALA},k} \in \mathbb{R}^{n_u}
```

For a two-input system:

```math
\Delta d_{\text{CALA},k}
=
\begin{bmatrix}
\Delta d_x \\
\Delta d_y
\end{bmatrix}
```

This correction is not applied directly as an extra plant input after MPC. Instead, it is injected into the MPC prediction model by modifying the disturbance estimate:

```math
\hat d_{\text{eff},k} = \hat d_k + \Delta d_{\text{CALA},k}
```

This is important because CALA becomes part of the predictive model, not merely an after-the-fact controller.

---

## CALA Feature Map

CALA does not choose a single global correction. Instead, it uses a feature map:

```math
\phi(x,t)
=
\begin{bmatrix}
\phi_1(x,t) \\
\phi_2(x,t) \\
\vdots \\
\phi_m(x,t)
\end{bmatrix}
```

Each feature describes the current nonlinear region or context.

In the implementation, the feature map uses the existing vortex field centres and widths. These are used as RBF feature centres:

```math
\phi_i(p,t)
=
\exp\left(
-\frac{\|p-c_i(t)\|^2}{\ell_i^2}
\right)
```

where:

- `p` is the global position;
- `c_i(t)` is the current vortex centre;
- `ell_i` is the feature width, based on the vortex sigma;
- `phi_i` is large when the robot is near that region.

The feature map may also include:

1. a bias feature, always active;
2. time features such as:

```math
\frac{1+\sin(\omega t)}{2},
\quad
\frac{1+\cos(\omega t)}{2}
```

These time features help CALA represent corrections that depend on the phase of the rotating background wind or time-varying vortex gains.

The features are normally normalized:

```math
\sum_i \phi_i(x,t) = 1
```

so that the final CALA correction is a weighted blend of local corrections.

---

## CALA Action Distributions

Each feature owns a continuous action distribution for each input channel.

For feature `i` and input channel `j`:

```math
a_{ij} \sim \mathcal{N}(\mu_{ij}, \sigma_{ij}^2)
```

The sampled action is clipped to the normalized range:

```math
a_{ij} \in [0,1]
```

Then it is mapped to a physical disturbance correction:

```math
\Delta d_{ij}
=
2d_{\max,j}(a_{ij}-0.5)
```

Thus:

| Normalized action | Physical meaning |
|---:|---|
| `0.0` | maximum negative correction |
| `0.5` | zero correction |
| `1.0` | maximum positive correction |

The final CALA correction is the feature-weighted blend:

```math
\Delta d_{\text{CALA},k}
=
\sum_{i=1}^{m}
\phi_i(x_k,t_k)\Delta d_i
```

where:

```math
\Delta d_i
=
\begin{bmatrix}
\Delta d_{i1} \\
\Delta d_{i2} \\
\vdots
\end{bmatrix}
```

So each region has its own preferred correction, and the active features determine which corrections matter at the current state.

---

## Low-Frequency CALA Trials

The selected learning mode is:

> Option A: low-frequency, non-overlapping trials.

One CALA trial lasts exactly one MPC horizon:

```math
T_{\text{trial}} = hT_s
```

For example, if:

```math
h=20, \quad T_s=0.1
```

then:

```math
T_{\text{trial}} = 2.0\text{ seconds}
```

The trial structure is:

```text
trial 1: k = 0       to h-1
trial 2: k = h       to 2h-1
trial 3: k = 2h      to 3h-1
...
```

A new CALA action is sampled only at the beginning of each trial. The sampled correction is then held constant for the duration of the trial.

---

## Trial Lifecycle

### 1. Begin Trial

At the start of a trial, CALA computes the current feature activations:

```math
\phi_k = \phi(x_k,t_k)
```

It samples local actions from the current CALA distributions:

```math
a_{ij} \sim \mathcal{N}(\mu_{ij},\sigma_{ij}^2)
```

These are converted into a blended correction:

```math
\Delta d_{\text{CALA},k}
=
\sum_i \phi_i(x_k,t_k)\Delta d_i
```

This correction is held fixed for the full trial.

---

### 2. Solve MPC With Corrected Disturbance Estimate

The MPC uses:

```math
\hat d_{\text{eff},k}
=
\hat d_k + \Delta d_{\text{CALA},k}
```

inside the prediction horizon.

The controller still solves the usual MPC problem, but the disturbance offset is modified by CALA.

The trial-start predicted state sequence is saved:

```math
\hat X_{k:k+h|k}
=
\left\{
\hat x_{k+1|k},
\hat x_{k+2|k},
\dots,
\hat x_{k+h|k}
\right\}
```

---

### 3. Run Closed Loop for `h` Steps

The controller continues operating in receding-horizon mode. MPC still replans every step, but the CALA correction is held fixed until the trial ends.

The actual closed-loop states are recorded:

```math
X^{\text{actual}}_{k:k+h}
=
\left\{
x_{k+1},
x_{k+2},
\dots,
x_{k+h}
\right\}
```

---

### 4. Compute Horizon Prediction Error

At the end of the trial, CALA compares the trial-start prediction against the actual closed-loop states:

```math
e_{k+i}
=
x^{\text{actual}}_{k+i}
-
\hat x_{k+i|k}
```

for:

```math
i=1,2,\dots,h
```

The horizon prediction error is:

```math
J_{\text{pred}}
=
\sum_{i=1}^{h}
\gamma^{i-1}
e_{k+i}^{T}Q_{\text{CALA}}e_{k+i}
```

where:

- `gamma` is a discount factor;
- `Q_CALA` weights position and velocity prediction error.

An additional terminal error can be included:

```math
J_{\text{terminal}}
=
e_{k+h}^{T}Q_{\text{CALA}}e_{k+h}
```

A small correction effort penalty is also used:

```math
J_{\text{effort}}
=
\left\|\Delta d_{\text{CALA},k}\right\|^2
```

The total CALA cost is:

```math
J_{\text{CALA}}
=
J_{\text{pred}}
+
\lambda_T J_{\text{terminal}}
+
\lambda_u J_{\text{effort}}
```

The reward is:

```math
R_k = -J_{\text{CALA}}
```

---

## Closed-Loop Prediction Error vs Open-Loop Error

This method uses closed-loop prediction error.

That means the predicted sequence saved at the beginning of the trial is compared against the actual trajectory followed by the receding-horizon controller.

This is not a pure open-loop model validation test. It measures:

> How well did the horizon prediction made at the start of the trial forecast the actual closed-loop path that followed?

This is useful because the reward is tied to real closed-loop behaviour, not an artificial open-loop rollout.

---

## Reference-Frame Convention

The current MPC is solved in the target-relative frame:

```python
controller.solve(x - xr, u)
```

Therefore, the CALA prediction error should usually also be computed in the same frame.

The predicted sequence used for CALA reward should be:

```python
current_plan_ref = controller.result_state_sequence.reshape(controller.h, controller.nx)
```

The actual state used for CALA reward should be:

```python
x_actual_ref = x - xr_next
```

where `xr_next` is the target state at the same time as the new actual plant state.

This avoids mixing target motion error into the disturbance-learning reward.

For visualization, the predicted sequence can still be converted back to the global frame:

```python
current_plan_global = current_plan_ref + xr
```

and stored as before.

---

## CALA Update Rule

CALA maintains a running reward baseline:

```math
\bar R_k
```

The advantage is:

```math
A_k = R_k - \bar R_k
```

If the reward is better than the baseline:

```math
A_k > 0
```

then the sampled action is reinforced:

```math
\mu_{ij} \leftarrow \mu_{ij}
+ \alpha_{\mu}\phi_i A_k(a_{ij}-\mu_{ij})
```

and variance is reduced:

```math
\sigma_{ij} \leftarrow
\sigma_{ij}
\left(1-\alpha_{\sigma}\phi_i A_k\right)
```

If the reward is worse than the baseline:

```math
A_k < 0
```

then the sampled action is discouraged:

```math
\mu_{ij} \leftarrow \mu_{ij}
- \alpha_{\mu}\phi_i |A_k|(a_{ij}-\mu_{ij})
```

and variance is increased:

```math
\sigma_{ij} \leftarrow
\sigma_{ij}
\left(1+\alpha_{\sigma}\phi_i |A_k|\right)
```

Feature activation controls credit assignment. If a feature was strongly active at the start of the trial, it receives a larger update. If it was nearly inactive, it receives little or no update.

## Required MPC Hook

The MPC `solve()` method should accept an optional CALA correction:

```python
def solve(self, x0, u0, update_disturbance_estimate=True, d_cala=None):
```

The internal disturbance parameter should be updated as:

```python
if self.disturbance:

    if d_cala is None:
        self.d_cala = np.zeros((self.nu, 1))
    else:
        self.d_cala = np.asarray(d_cala, dtype=float).reshape(self.nu, 1)

    self.d_eff = self.d_hat + self.d_cala
    self.d_hat_param.value = self.d_eff
```

The key point is that `d_hat` should not be overwritten. It remains the one-step residual estimate.

CALA produces a separate residual correction:

```math
\Delta d_{\text{CALA}}
```

The MPC plans with:

```math
\hat d_{\text{eff}} = \hat d + \Delta d_{\text{CALA}}
```

## Integration Pattern in `main.py`

The expected integration pattern is:

```python
import cala_horizon
```

After creating the nonlinear field:

```python
field = nonlinear_field.VortexField()
disturbor = disturbance_generator.Disturbance(field=field, x=x, t=t)
```

create the feature map:

```python
feature_map = cala_horizon.VortexFeatureMap(
    field=field,
    sigma_scale=1.25,
    include_bias=True,
    include_time=True,
    normalize=True,
)
```

After creating the controller:

```python
controller = mpc.MPC(x - xr)
```

create the CALA learner:

```python
cala = cala_horizon.CALAHorizonResidual(
    feature_map=feature_map,
    nu=controller.nu,
    nx=controller.nx,
    h=controller.h,
    d_corr_max=0.50,
    mu_init=0.5,
    sigma_init=0.25,
    sigma_min=0.03,
    sigma_max=0.60,
    lr_mu=0.12,
    lr_sigma=0.06,
    discount=0.98,
    terminal_weight=1.0,
    effort_weight=0.02,
    seed=1,
)
```

Inside the control loop:

```python
xr = target.evolve(t)

if cala.should_start_trial():
    d_cala = cala.begin_trial(x_global=x, t=t)
else:
    d_cala = cala.current_correction()

controller.solve(
    x - xr,
    u,
    update_disturbance_estimate=True,
    d_cala=d_cala,
)

current_plan_ref = controller.result_state_sequence.reshape(
    controller.h,
    controller.nx,
).copy()

current_plan_global = current_plan_ref.copy() + xr

if cala.active and cala.trial_prediction is None:
    cala.attach_prediction(current_plan_ref)

u = controller.result_control_next.flatten()

d = disturbor.evolve(field=field, x=x, t=t)
x = plant.evolve(x, u, d, disturb=True)

t_next = t + controller.Ts
xr_next = target.evolve(t_next)

x_actual_ref = x - xr_next
cala_result = cala.record_actual(x_actual_ref)

if cala_result is not None:
    print(
        f"CALA trial completed at t={t_next:.2f}: "
        f"reward={cala_result['reward']:.4f}, "
        f"pred_error={cala_result['prediction_error']:.4f}, "
        f"d_cala={cala_result['d_cala']}, "
        f"exploration={cala_result['exploration']:.4f}"
    )

data.stage(
    phase='controller',
    step=t,
    A_hat=controller.A,
    B_hat=controller.B,
    d_hat=controller.d_hat,
    d_cala=d_cala,
    d_eff=getattr(controller, "d_eff", controller.d_hat),
    d=plant.d,
    target=xr,
    state=x,
    input=u,
    plan=current_plan_global,
)

data.store(flush_after=True)

t = t_next
```

## Interpretation

The current MPC already provides a good local approximation of the nonlinear field:

```math
\hat d_k \approx d(p_k,t_k)
```

CALA does not replace this estimate. Instead, it learns how to correct it:

```math
\hat d_{\text{eff},k}
=
\hat d_k + \Delta d_{\text{CALA},k}
```

The learning signal is the prediction error accumulated over the MPC horizon:

```math
R_k
=
-
\left[
\sum_{i=1}^{h}
\gamma^{i-1}
\left\|
x^{\text{actual}}_{k+i}
-
\hat x_{k+i|k}
\right\|_{Q_{\text{CALA}}}^{2}
+
\lambda_T
\left\|
x^{\text{actual}}_{k+h}
-
\hat x_{k+h|k}
\right\|_{Q_{\text{CALA}}}^{2}
+
\lambda_u
\left\|
\Delta d_{\text{CALA},k}
\right\|^2
\right]
```

The MPC horizon therefore serves two roles:

1. the prediction horizon for control;
2. the trial duration for CALA learning.

This gives a stronger learning-control architecture than having CALA learn the disturbance field directly:

> The linear/MPC component handles the locally reliable approximation. CALA learns the residual correction needed when that local approximation breaks down across the nonlinear field.

---

## Conceptual Summary

| Component | Role |
|---|---|
| `VortexField` | Generates the true nonlinear disturbance field |
| `MPC.d_hat` | Estimates the current local disturbance from one-step prediction error |
| `VortexFeatureMap` | Identifies the current nonlinear region using RBF/time features |
| `CALAHorizonResidual` | Learns a feature-dependent correction to `d_hat` |
| `d_eff` | Corrected disturbance estimate used by MPC prediction |
| MPC horizon `h` | Defines both the control prediction window and CALA trial length |
| CALA reward | Negative closed-loop horizon prediction error |

The resulting architecture is:

```text
true nonlinear field
        ↓
plant experiences d(p,t)
        ↓
MPC estimates local d_hat from one-step residual
        ↓
CALA adds feature-dependent correction d_cala
        ↓
MPC plans using d_eff = d_hat + d_cala
        ↓
closed-loop horizon prediction error updates CALA
```

In one sentence:

> CALA learns the residual error of the MPC's own local disturbance approximation, using the MPC prediction horizon as the learning trial.
